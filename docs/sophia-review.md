# Response evidence for Sophia David's CellGen comments

This is a software and evidence review, not biological validation. It uses the current Python package, browser implementation and saved ten-genome EuSCAPE analysis. The manuscript itself was not edited.

| Question | Observed behaviour and evidence | Repair or remaining choice |
| --- | --- | --- |
| What is a cell and can it be empty or multiple? | Both parsers accept `()chr` and `()chr;()chr2`; grammar permits empty child sets and multiple cells. An entirely empty cell is invalid. Importers group all records in one file into one cell. | Specification now states this. The Methods claim that empty chromosomes and multiple cells are invalid needs replacement. A chromosome requirement for a study can be a separate inclusion rule. |
| What do the importers need? | GenBank requires parsed `LOCUS` records; GFF3 accepts features, sequence-region directives and optional embedded FASTA. It rejects malformed rows/coordinates. EMBL has no importer. | `docs/import.md` specifies accepted types and fields; EMBL remains a proposed future format, not advertised support. |
| How are plasmids, fragments and standalone elements represented? | Explicit plasmid/chromosome metadata drives classification, with a fallback ID-name inference only for the literal words `plasmid` or `chromosome`. A full-span GenBank mobile element becomes a bare entity. Opaque fragments remain `type="unknown"`; multi-record files remain one cell. | Fixed previous chromosome default and GFF3 MGE-to-plasmid misclassification. Unknown biological replicon identity is left for review. |
| Which genes and AMR features survive? | Genes inside annotated structural features survive. Uncontained genes are omitted by default. Python and browser can retain all, or select exact IDs/names/locus tags; the browser reports retained/omitted counts. | Added explicit selection. No name-based AMR heuristic or invented MGE parent. A chromosomal AMR call requires annotation and selection; if annotations are insufficient, the user must improve the source or manually edit the record. |
| How is containment determined? | Smallest strict coordinate enclosure on the same record, with equal boundaries and partial overlaps as siblings; equal-size parent ties follow source order. GFF3 gene/CDS pairs at the same span collapse when `Parent` explicitly links the CDS to its gene. | GFF3 `Parent` is not a general hierarchy override: more complex multi-parent/discontinuous features remain unresolved and need a design decision. The hierarchy is an annotation interpretation, not proof of mobility. |
| Why ten KPC genomes and what does similarity mean? | Selected by exact KPC annotation, assembly contiguity and KPC contig size, then ranked by contig count/sample ID. Reproduced saved calls for all ten from the EuSCAPE evidence pack. Similarity compares the KPC-containing Tn4401 subtree plus generic plasmid root, not whole plasmid architecture. | `analysis/euscape_results/REVIEW.md` gives versions, IDs, coordinates, detector calls, exact pairwise facts and scores. It explicitly rules out sequence identity/transmission conclusions. |
| Why are AT022 IS features absent? | Saved ISEScan has IS1182 at 82,683–85,496, crossing the Tn4401a start at 83,914; no saved IS call lies wholly inside its 83,914–93,820 interval. | No expected IS was forced into the tree. Expert review of sequence and reference boundaries is needed to distinguish detector omission, boundary choice and variation. |
| Why are labels and DE016 nesting odd? | Numbered ISEScan names such as `IS21_259` are displayed as family `IS21`; raw names remain in the call table. DE016's Tn4401 resolution site 201–321 lies inside IS21 76–903 by coordinates, but has Tn4401 family. | Tn4401-labelled resolution sites no longer acquire IS parents in the Figure 3 normaliser; corrected records, scores and figure regenerated. Family-vs-name figure labelling and biology need expert confirmation. |

Suggested Methods replacement, subject to coauthor review:

The live Methods text currently says, “The valid records included nested entities, quoted labels and escaped attribute values, while invalid records included empty chromosomes, multiple cells and malformed syntax.” This conflicts with both the Results description and the shared fixture set: the 34 conformance cases have **19 valid** and **15 invalid** CellGen strings, including valid `()chr` and valid semicolon-separated cells. The neighbouring phrase “genome annotation files??” should say “CellGen strings” if it refers to these parser cases.

Replace that Methods sentence with:

> The 19 valid CellGen strings included empty chromosomes, multiple cells, nested entities, quoted labels and escaped attribute values; the 15 invalid strings tested malformed syntax and duplicate attributes.

For the importer description, use:

> A CellGen document contains one or more cells separated by semicolons. Each cell contains one or more top-level chromosome or entity records. An empty chromosome or entity bracket pair indicates that no child entity is represented. The GenBank and GFF3 importers group all sequence records from one input file as one cell and preserve known sequence provenance and feature coordinates; they do not infer cell boundaries, plasmid identity for unclassified contigs, or unannotated mobile elements. By default, uncontained genes are omitted, while selected annotated genes can be retained on their source replicon.

Suggested Figure 3 Results wording, subject to expert biological review:

> We selected ten EuSCAPE assemblies with a single annotated KPC hit, a largest contig of at least 5 Mb and a KPC-bearing contig shorter than 500 kb, then compared the annotated Tn4401-family carrier hierarchies. Similarity is the multiset Jaccard percentage of entity identities and immediate containment relationships after normalising sample-specific labels and excluding coordinates. It describes shared annotated structure, rather than sequence identity, plasmid identity or transmission. The AT022 record has no insertion-sequence call fully contained within the inferred Tn4401a interval; the adjacent IS1182 call overlaps its boundary and merits sequence-level review.
